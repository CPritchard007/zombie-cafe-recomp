# Zombie Cafe Android recovery

## Playable web edition

The first browser version is in [`web/`](web/README.md). Run `cd web && npm start`, then open `http://127.0.0.1:4173`. It includes cooking, sales, decorating, local saves and the original assets. See the web README for scope and remaining parity work.

Recovered from `ZombieCafe-JP-English-v0.1.apk` as the reference for a future web recreation.

## Application

**Rebuilt application:** [recovered/ZombieCafe-rebuilt-debug.apk](recovered/ZombieCafe-rebuilt-debug.apk)

The APK was rebuilt from decoded Android resources and smali, with the original native ARM library and assets. It is signed with a local development key, not the publisher's original key. Its package is `com.capcom.zombiecafeandroidJP`, version code **78**, version name **ZombieCafeAndroid 1.7.0**, minimum SDK **10**, target SDK **24**. The input filename's `v0.1` is not the internal application version.

Build and signature checks passed. Runtime gameplay has **not** been tested on a compatible Android device. The app only packages the old `armeabi` native ABI; it requires a compatible 32-bit ARM runtime or ARM translation. A differently signed installed copy cannot be updated using this development APK. Online features depend on services not included in the APK; their availability has not been checked.

Native export completed for **8,670 functions**, covering all **6,412 unique exported code addresses**, with no failed exports after retry. **1,273 files contain decompiler warnings**; successful export does not establish semantic correctness. See `reports/native-summary.json` for coverage and the warning list. A spot check verifies that the recipe deserializer includes all numeric-field reads after the string destructor. Automatic non-return inference was disabled to prevent incorrect truncation of returning functions.

The readable Java and native pseudocode are **decompiler output**, not the original source tree. Native pseudocode is reference material, not compilable C++. The working Android rebuild uses smali and the original `.so`; it does not compile the decompiled Java or replace native game logic. A first playable browser recreation is now available in `web/`; it uses new JavaScript implementations rather than compiling this pseudocode.

## Repeat the work

Tools are installed locally under `.tools/`: JADX 1.5.3, Apktool 2.11.1, Ghidra 11.3.2. Java 17 runs JADX/Apktool; Ghidra uses the available Homebrew Java 22. Asset exports require Python 3 and Pillow (`requirements-recovery.txt`).

```sh
# Re-decode the Android project and Java sources (replaces recovered/android):
./scripts/decompile.sh

# Rebuild, align, sign with a local debug key, and verify:
./scripts/rebuild_android.sh

# Refresh browser-friendly assets and recipe data:
python3 scripts/export_assets.py
python3 scripts/export_recipes.py

# Re-run native analysis/export (several minutes):
./scripts/decompile_native.sh

# Verify extracted files and rebuilt asset/library fidelity:
python3 scripts/verify_recovery.py
python3 scripts/summarize_native.py
```

Set `SDK_BUILD_TOOLS` to your Android SDK build-tools directory when running the rebuild on another machine. Local debug signing material is excluded from version control in `.tools/keys/`.
